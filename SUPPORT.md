# Support

Quatopsy is research software maintained without a commercial support SLA.

## Where to ask

- Use a GitHub issue for reproducible defects, documentation gaps, adapter requests, and bounded feature proposals.
- Use the structured issue forms so reports include version, platform, command, declared input format, and redacted reproduction details.
- Use [GitHub private vulnerability reporting](https://github.com/kabudu/quatopsy/security/advisories/new) for security concerns.

Before filing, run the latest `master` when practical, review the [documentation](README.md#documentation), and check existing issues.

## What maintainers cannot provide

Maintainers cannot approve trajectories for flight, validate mission procedures, interpret classified or proprietary telemetry, authorize actuator commands, certify hardware, or provide emergency operational support. Do not use a GitHub issue as a mission-operations escalation channel.

Public issues must not contain credentials, personal data, proprietary logs, export-controlled material, or sensitive incident evidence. Reduce cases to synthetic or explicitly redistributable inputs.
